# reflect

같은 교정이 두 번 나오면 규칙이나 검사로 올린다(README의 "교훈", ADR-0001의 14번). 이유: 글로 쓴 교훈은 읽히지 않고, 검사는 읽지 않아도 지켜진다.

## 절차

1. `docs/journal/`의 이번 슬라이스 일지(날짜 범위는 plan의 시작부터 지금까지)에서 "관찰"과 "결정 (AI)"를 읽는다.
2. 같은 교정이 두 번 이상인지 묶는다. 표현이 달라도 같은 원인이면 같은 교정이다. 근거로 일지의 날짜와 스텝 번호를 적는다.
3. 묶은 것마다 올릴 곳을 제안한다. 강한 것부터다.

| 올릴 곳 | 쓸 때 |
|---|---|
| 검사(훅, `docs_lint.py`, `check.sh`, ArchUnit) | 기계가 판정할 수 있다 |
| 기준 코드 | 모양의 문제다(ADR-0001의 15번) |
| ADR의 요구 | 판단이 필요하다. AI가 기본으로는 틀릴 것만 쓴다 |
| 스킬이나 `AGENTS.md` | 절차의 문제다 |

4. 제안을 사용자에게 보인다. 한 번에 세 개까지다. 사용자가 고른 것만 다음 스텝에서 만든다.
5. 올릴 것이 없으면 "없음"이라고 말한다. 억지로 만들지 않는다.

## 하지 않는 일

- 규칙, ADR, 스킬, 훅을 직접 고치지 않는다. 같은 교정이 한 번뿐인 것은 규칙으로 올리지 않는다.
- 일지의 기존 내용을 고치지 않는다.
