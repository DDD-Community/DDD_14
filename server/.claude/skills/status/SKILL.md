# status

상태는 저장하지 않고 문서와 git에서 계산한다(ADR-0001의 10번). 이유: 상태 파일은 낡는다. 문서에서 계산하면 낡지 않고, AI가 상태를 추론하다 틀리는 일이 없다.

## 절차

1. `python3 scripts/status.py`를 실행한다.
2. 출력은 네 부분이다: 브랜치, 문서의 상태별 개수와 승인을 기다리는 문서, 마지막 일지의 마지막 스텝의 "남은 일", 계산한 단계와 그 이유.
3. 결과를 사용자에게 짧게 알린다. 단계는 추정이다. 구현과 검증이 끝났는지는 `scripts/check.sh`의 결과가 있어야 안다.
4. 출력이 서로 어긋나면(예: plan이 승인인데 테스트가 없음) 어느 쪽이 맞는지 추측하지 않고 사용자에게 묻는다.

## 하지 않는 일

- `status.py`의 출력을 파일에 저장하지 않는다.
- 계산한 단계를 근거로 사용자의 승인을 대신하지 않는다.
