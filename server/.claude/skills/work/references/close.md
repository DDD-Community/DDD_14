# close — 종료

슬라이스를 닫는다. 일지, 수정의 줄, plan의 상태, 커밋, push, PR을 AI가 하고, 병합은 사람이 한다(작성자 외 서버 팀원 한 명의 승인과 CI 통과. CI가 생기기 전에는 CI 대신 PR에 `check.sh` 통과를 적는다). `explain-diff`는 사용자가 요청할 때만 한다.

## 읽는 것

- 이 슬라이스의 일지와 plan.
- `references/shared/커밋과-PR.md`, `shared/일지-쓰는-법.md`.

## 절차

1. `python3 scripts/status.py`로 남은 일이 없는지 확인한다. plan의 작업이 모두 `완료`가 아니면 닫지 않는다.
2. 고친 문서에 수정의 줄이 있는지, AI가 고친 곳에 "확인이 필요하다"가 있는지 확인한다.
3. 정책과 ADR의 MUST를 네 가지로 대조한다(`review` 스킬의 conformance 절차, `doc-reviewer`): 지키고 테스트가 강제한다, 지키지만 강제가 없다, 어긋난다, 아직 없다. 어긋남이 남아 있으면 닫지 못한다(ADR-0001의 13번).
3-1. `docs/review/`에 이 슬라이스의 리뷰 중 "처리"가 없는 것이 있으면 닫지 않는다. `python3 scripts/status.py`가 처리 대기 리뷰를 보여 준다(ADR-0001의 32번).
4. (선택) 같은 교정이 일지에 두 번 나왔는지 `reflect` 스킬로 확인한다. 사용자가 원하지 않으면 건너뛴다.
5. plan의 상태를 `닫음 (<날짜> 일지 스텝 N)`으로 바꾼다.
6. 커밋하고 push하고 PR을 만든다. 절차는 `shared/커밋과-PR.md`다. 원격 저장소가 없으면 커밋까지만 한다.
7. PR의 설명에 이 슬라이스 일지의 "결정 (AI)" 목록을 넣는다. 사용자가 이 목록을 보고 병합한다.
8. 병합은 하지 않는다. 사용자에게 PR을 알리고 끝낸다.

## 하지 않는 일

- 병합, `main`과 `develop`에 직접 push, force push를 하지 않는다. 이유: 병합은 사람이 한다(ADR-0001의 3번).
- `check.sh`를 거치지 않은 커밋을 push하지 않는다.
