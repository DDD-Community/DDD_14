# 리뷰 결과 합치기

리뷰어(`doc-reviewer`, `code-reviewer`)의 리포트를 받아 다음 행동으로 바꾸고 `docs/review/`에 기록하는 절차다. 리포트의 형식은 `.claude/agents/<리뷰어>.md`에 있다. 리뷰 문서의 위치와 수명은 `docs/README.md`의 "문서의 지도"다.

## 절차

1. 리포트 전문을 사용자에게 그대로 보인다. 경로만 알리지 않는다. 이유: 사용자가 받아들일지 정하는 근거다.
2. **슬라이스의 리뷰 문서 `docs/review/NN-<슬라이스>.md`에 이번 리뷰의 절을 더한다.** NN은 plan의 번호다. 문서가 없으면 만든다. 아래 "리뷰 문서의 양식"을 따른다. 리포트의 지적, 확인 필요, Objections를 **그대로** 옮긴다. 요약하거나 고치지 않는다. 이유: 리뷰어가 무엇을 찾았는지가 기록이다.
3. 판정으로 분기한다.

| 판정 | 뜻 | 행동 |
|---|---|---|
| `PASS` | 차단과 권고가 없다 | 다음으로 간다. 처리할 지적이 없으므로 "처리"에 "지적 없음"을 쓴다 |
| `PASS_WITH_FIXES` | 권고만 있다 | 권고를 보이고 반영 여부를 사용자에게 묻는다 |
| `FAIL` | 차단이 있다 | 임의로 해결하지 않는다. 차단의 근거를 확인하고 코드 문제면 고친다. 문서가 틀렸을 수 있으면 사용자에게 올린다 |

4. **지적마다 처리를 정한다.** 누가 정하는지는 아래 표를 따른다.

| 지적 | 처리를 정하는 쪽 |
|---|---|
| 차단 중 코드를 고치면 되는 것(근거가 분명하다) | AI가 반영하고 `받아들임`으로 기록한다 |
| 권고, 설계 제안, 정책과 문서의 지적, 근거가 의심되는 차단 | 사용자에게 묻는다. 사용자가 정한다 |
| `받아들이지 않음` | 사용자만 정한다. AI는 리뷰어의 지적을 스스로 거절하지 않는다 |

5. 정해지면 그 리뷰의 절 안에 **"처리"를 더한다.** 이미 쓴 줄은 고치지 않는다(README의 "쌓기만 한다"). 처리가 나중에 바뀌면 "처리의 변경" 줄을 아래에 더한다.
6. 한 대상의 리뷰는 2라운드에서 끝낸다. 리뷰어를 부를 때 라운드 번호(r1, r2)를 넘기고, r2가 마지막이라고 알린다. 사용자가 허락하지 않으면 세 번째로 부르지 않는다. 같은 지적이 두 라운드 연속 나와도 중단하고 사용자에게 보고한다. 이유: 고치면 새 지적이 생겨서 리뷰가 수렴하지 않는다(2026-11-24 리허설). 기준을 낮춰 통과시키는 것도 막는다.

| r2의 결과 | 다음 |
|---|---|
| 차단 0건 | 권고를 사용자에게 한 번에 묶어 묻고 다음 관문으로 간다 |
| 차단이 남음 | 더 부르지 않는다. 차단을 고친 내용과 남은 것을 사용자에게 보이고, 승인 관문에서 사용자가 정한다(고친 것으로 승인, 질문으로 올림, 한 라운드 더) |
7. 결과의 요약(판정, 차단과 권고의 개수, 받아들인 것과 받아들이지 않은 것의 개수)과 리뷰 문서의 경로를 일지에 쓴다.
8. `Objections`(리뷰어의 이견)가 있으면 사용자에게 그대로 전달한다. 리뷰어가 문서를 고치지 않는다.

## 리뷰 문서의 양식

리뷰 문서는 상태의 줄을 쓰지 않는다(README의 "상태의 줄").

```markdown
# 리뷰 NN. <슬라이스 이름>

슬라이스 NN(`docs/plan/NN-<슬라이스>.md`)의 리뷰를 쌓는다. 리뷰 한 번이 절 하나다.

## <대상> r<k> (<리뷰어>, <절차>)

- 대상: 점검한 파일이나 diff의 범위
- 일지: YYYY-MM-DD 스텝 N
- 판정: PASS, PASS_WITH_FIXES, FAIL (차단 N건, 권고 N건)

### 지적

(리포트의 "지적"을 그대로. 지적마다 ID(DOC-n, CODE-n, SP-n)가 있다)

### 확인 필요

(리포트 그대로)

### Objections

(리포트 그대로)

### 처리 (YYYY-MM-DD 일지 스텝 N)

| 지적 | 처리 | 이유 | 결정한 사람 |
|---|---|---|---|
| DOC-1 | 받아들임 | 어떻게 반영했는가(파일, 줄) | 사용자 |
| DOC-2 | 받아들이지 않음 | 왜 받아들이지 않는가 | 사용자 |
| CODE-1 | 보류 | 무엇을 기다리는가 | 사용자 |
```

`<대상>`은 문서, plan, 코드, 대조 중 하나다. 지적의 ID는 그 절 안에서만 쓴다.

처리의 값은 `받아들임`, `받아들이지 않음`, `보류`다. `받아들이지 않음`에는 이유를 반드시 적는다. `보류`는 닫기 전에 다른 값으로 바뀌어야 한다.

## 쓰는 이유

- 받아들인 것과 받아들이지 않은 것을 함께 남기면, 다음에 같은 지적이 다시 나왔을 때 이미 판단한 것을 알 수 있다.
- 같은 지적이 반복해서 나오면 `reflect`가 규칙이나 검사로 올리자고 제안한다.
