# 일지 쓰는 법

스텝(한 번의 작업 단위)이 끝나면 일지를 쓴다. 규칙의 정본은 `docs/README.md`다. 이 파일은 양식만 적는다. 일지는 쌓기만 한다. 이미 쓴 내용을 지우거나 고치지 않는다(`docs-lint`가 막는다).

## 파일

`docs/journal/YYYY-MM-DD-<이름>.md`. 이름은 `git config harness.handle`의 값(소문자 영문, 숫자, 하이픈)이다. 그날 내 첫 스텝이면 파일을 만든다. 다른 사람의 일지는 고치지 않는다(`journal-check`가 막는다).

```markdown
# 작업 일지 — YYYY-MM-DD

단계: **<지금 단계>**
```

## 스텝의 양식

```markdown
## 스텝 N. <한 줄 제목>

**요청 (사용자)**: 사용자가 말한 것.

**결정 (사용자)**: 사용자가 정한 것. 없으면 이 항목을 쓰지 않는다.

**한 일 (AI)**:
1. AI가 한 일.

**결정 (AI)** (확인이 필요하다):
- 문서가 정하지 않았거나 사용자가 말하지 않아서 AI가 정한 것.

**관찰**:
- 겪은 함정이나 교정. 같은 교정이 두 번 나오면 규칙이나 검사로 올릴 후보다.

**남은 일**:
- 다음 스텝의 후보.
```

## 쓰는 이유

- "결정 (AI)"는 AI가 몰래 정한 것을 사용자가 병합 전에 볼 수 있게 한다. PR의 설명에 이 목록을 넣는다.
- "관찰"은 `reflect` 스킬이 같은 교정의 반복을 찾는 자리다.
- 마지막 스텝의 "남은 일"이 다음 세션의 시작점이다(`AGENTS.md`, `scripts/status.py`).
