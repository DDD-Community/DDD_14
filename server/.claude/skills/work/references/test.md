# test — 테스트 작성

plan의 작업 하나가 다루는 AC와 R을 `test-author`가 구현을 보지 않고 테스트로 쓰고, 실행해서 red를 확인한다. 이유: 구현자가 자기 버그를 통과시키는 테스트를 쓰지 못하게 하려는 것이다(ADR-0001의 8번).

## 읽는 것 (너, 메인 세션)

- plan의 그 작업 한 줄, 그 작업의 AC와 R의 줄.
- `docs/adr/0004-테스트-전략.md`(테스트의 규칙). 다른 ADR은 읽지 않는다.

## 절차

1. 작업의 상태를 `진행`으로 바꾼다.
2. `test-author`를 부른다. 입력은 plan 경로, 작업 번호, 그 작업의 AC·R이 있는 파일 경로뿐이다. 내용을 붙여 넣지 않는다. 구현은 넘기지 않는다.
3. 돌아온 노트(`_workspace/test-author-NN-<작업 번호>.md`)를 읽는다. 모든 AC·R에 테스트가 있는지, 새 테스트가 모두 red인지 확인한다.
4. 노트의 "사용자 질문"에 답이 필요한 것이 있으면 사용자에게 묻는다. 한 번에 세 개까지다. 문서가 기대 동작을 말하지 않은 곳은 테스트를 쓰지 않았으므로, spec이나 domain을 먼저 정해야 한다.
5. red가 아닌 테스트(처음부터 통과)가 있으면 이유를 본다. 이미 구현된 동작이거나 테스트가 아무것도 확인하지 않는 것이다. 후자면 `test-author`를 한 번 다시 부른다.
6. 스텝이 끝나면 일지를 쓴다.

## 하지 않는 일

- 구현을 읽고 테스트의 기대값을 정하지 않는다. 기대값은 문서에서만 온다.
- 테스트를 통과시키려고 `test-author`의 테스트를 고치지 않는다. 테스트가 틀렸다고 판단하면 일지에 적고 `test-author`를 다시 부른다.
