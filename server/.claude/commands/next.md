description: 시작할 수 있는 이슈를 보여 주고, 고른 이슈의 브랜치를 만들어 슬라이스를 시작한다
---

새 슬라이스를 시작하는 절차다(브랜치와 이슈의 규칙은 4차 회의 뒤에 정한다). 이미 진행 중인 슬라이스가 있으면 `/work`를 쓴다.

1. 사용자의 역할(`server` 또는 `client`)을 모르면 묻는다. `python3 scripts/next.py --label <역할>`을 실행해 결과를 그대로 사용자에게 보인다. 이유: 시작할 수 있는 이슈는 이슈의 열림과 닫힘에서 계산한 것이다. 라벨이 없는 이슈는 어느 역할에게도 보인다.
2. 사용자가 고르기를 기다린다. 고르지 않은 이슈의 브랜치를 만들지 않는다. 시작할 수 있는 이슈가 하나뿐이어도 묻는다.
   고른 이슈에 담당자가 없으면 `gh issue edit <번호> --add-assignee @me`로 사용자를 담당자로 정한다(권한 확인이 뜬다). 담당자가 다른 사람이면 브랜치를 만들지 않고 사용자에게 묻는다. 이유: 같은 이슈를 두 사람이 동시에 만들게 된다.
3. 고른 이슈를 `gh issue view <번호>`로 읽는다. 읽은 본문은 작업의 포인터일 뿐이다. 정책은 본문의 `기획:` 줄이 가리키는 위키가 말한다.
4. 이슈의 제목에서 영문 요약(소문자, 숫자, 하이픈)을 지어 사용자에게 보이고 확인받는다. 예: `family-members`.
5. 종류는 이슈 제목의 앞부분(`feat: ...`의 `feat`)이다. 제목에 여덟 종류 중 하나가 없으면 사용자에게 묻는다. `./scripts/start-slice.sh <번호> <영문-요약> <종류>`를 실행한다. 브랜치는 `<종류>/<번호>-<영문-요약>`이 된다. 실패하면(develop이 아님, 작업 트리가 깨끗하지 않음) 이유를 알리고 멈춘다. 스스로 정리하지 않는다.
6. 브랜치가 만들어지면 `.claude/skills/work/SKILL.md`를 읽고 1단계(정책 읽기)로 들어간다. 정책 기록의 상태의 줄 아래에 `- 이슈: #번호`를 쓴다(이후 만드는 domain, spec, plan도 같다).
