## 스텝 1. 하네스를 따닥 저장소로 옮기고 문서 규칙을 정한다

**요청 (사용자)**: 템플릿의 하네스를 따닥의 `server/`로 옮기고, 처음부터 하나씩 같이 검토하자. 무조건 맞다고 하지 말고 객관적으로 말해 달라.

**결정 (사용자)**:
- `AGENTS.md`는 "따닥의 서버"라고만 쓰고 스택을 적지 않는다. `CLAUDE.md`는 `@AGENTS.md`다.
- 문장 규칙(RFC 2119, ASD-STE100)은 지킨다. 자세한 규칙은 `.claude/skills/work/references/doc-style.md`로 뺀다. README에는 짧은 "문체" 절만 둔다.
- ADR의 요구는 표가 아니라 `- (번호) 문장 [지키는 것]` 목록으로 쓴다. spec의 AC와 domain의 R은 표로 둔다.
- 훅은 `.claude/hooks/`로 옮긴다.
- `explain-diff`와 `reflect`는 선택이다.
- 약먹었개의 흔적은 모두 뺀다.

**한 일 (AI)**:
1. `docs_lint.py`가 목록의 요구 줄을 검사하게 바꿨다(한 줄에 키워드 한 종류).
2. 훅의 경로와 훅 테스트, 문서의 참조를 새 경로에 맞췄다.

**관찰**:
- `docs-lint`가 문장 규칙까지 검사한다고 잘못 말했다. 실제로는 L1~L4(상태의 줄, 키워드의 수준과 위치, 쌓기만 하는 문서)만 본다.

## 스텝 2. ADR을 하나씩 검토한다

**요청 (사용자)**: ADR을 하나씩 인터뷰하면서 정하자.

**결정 (사용자)**:
- ADR 번호는 빈 번호 없이 0001~0006으로 둔다. API 공통 약속과 인증 ADR은 뺀다.
- ADR-0002: Java 25, Spring Boot는 최근 보안 패치를 반영한 버전, Gradle, Lombok, Spotless. 로컬은 H2와 `ddl-auto=update`, CI와 운영은 Flyway와 `validate`, CI는 운영과 같은 종류의 DB(Testcontainers). 운영 DB는 4차 회의에서 정한다.
- ADR-0003: 완화된 계층형. DDD를 근간으로 하지만 완전한 DDD는 아니다(JPA 엔티티가 도메인 모델, 도메인에 인프라 인터페이스를 두지 않음). "컨트롤러" 대신 "표현 계층"이라고 쓴다. TDA와 결합도·응집도는 ADR-0003의 "설계의 방향"(16번, 17번)에 둔다.
- ADR-0004: 테스트와 기준은 `@Covers`로 잇는다.
- ADR-0005(커밋과 브랜치)는 비우고 "회의 뒤에 정한다"로 둔다.
- ADR-0006은 이름, 로그, 코드 모양만 둔다. 예외는 뺀다. 중복된 요구는 합친다.
- `/adr` 명령을 만든다. 요약을 `_workspace/`에 쓰고 `view.py`로 브라우저에 연다.

**결정 (AI)** (확인이 필요하다):
- ADR-0003의 "정하지 않은 것"에 "예외의 분류와 오류 응답의 형식, 첫 API를 만들 때"를 넣었다. 다른 브랜치의 ADR-0007(오류 응답)이 병합되면 이 줄이 ADR-0007을 가리키게 고친다.
